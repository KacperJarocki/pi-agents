# Rust Sensor

Turns frames captured on the gateway's Wi-Fi AP interface into
device-attributed **micro-flows**: both directions of one 5-tuple, oriented
from the device's point of view, flushed after 1 s of inactivity or 1 s after
the first packet (so aggregation adds at most 1 s of latency).

Each record carries packet timestamps (first/last), per-direction packet and
byte counts, TCP SYN / SYN-ACK / RST / FIN counts, an attempt outcome
(`Established`, `Rejected` on RST or ICMP unreachable, `Unanswered` for a SYN
with no reply before the flush, `NotApplicable`), the first DNS query name
sent to port 53, and a `continuation` flag when the 5-tuple was already
reported. A later answer to an unanswered SYN arrives as a continuation with
the updated outcome.

Devices are identified by client MAC from the dnsmasq lease file written by
`gateway-agent` (`/var/lib/gateway-agent/dnsmasq.leases` on the gateway node).
Frames to or from unknown MACs are counted as unattributed, not emitted.

## Layout

- `src/packet.rs`: bounds-checked Ethernet/802.1Q, IPv4/IPv6, TCP/UDP/ICMP parser.
- `src/attribution.rs`: lease parsing and MAC-based attribution.
- `src/lib.rs`: `FlowTable` (bounded micro-flow table) and `Sensor`.
- `src/proto.rs`: hand-written encoder for v2 `FlowEvent`/`HealthEvent`
  (field numbers checked against `schemas/events/v2/compatibility.json`).
- `src/spool.rs`: bounded on-disk spool (segmented append-only log with CRC).
- `src/forward.rs`: spool → `Publisher`, delivery acknowledgements, health events.
- `src/kafka.rs`: librdkafka publisher (feature `kafka`).
- `src/pcapfile.rs`: classic pcap reader for fixtures and offline replay.
- `src/main.rs`: binary.

The `FlowTable` has a hard capacity. When it is full the flow with the oldest
last packet is flushed early and `upsert` returns `UpsertResult::Evicted`;
callers must expose that as a metric and health event (`SensorStats::evictions`).

## Delivery

Every micro-flow is appended to the spool before it is sent and removed only
after Kafka acknowledges it (`acks=all`, idempotent producer, `linger.ms=20`,
no message timeout). The spool assigns `capture_sequence`; event IDs are
`<gateway_id>/<capture_sequence>`. Sequences are reserved in blocks of 4096 in
`<spool>/sequence`, so a restart skips ahead and never reuses an ID.

- **Broker outage**: events wait in librdkafka's bounded queue and then in the
  spool; they are sent in order when the broker returns.
- **Restart**: `<spool>/acked` holds the acknowledgement watermark written on
  every sync; entries at or above it are sent again (at-least-once; consumers
  deduplicate by event ID).
- **Spool full** (default 2 GiB, 64 MiB segments): the oldest segment is
  dropped and a `HealthEvent` of kind `SPOOL_LOSS` goes to `traffic.health.v2`
  with the cumulative lost count, first/last lost sequence and time range.
- Every 10 s the sensor also publishes `UNATTRIBUTED` and
  `FLOW_TABLE_EVICTION` deltas and a `HEARTBEAT` with the frame count.

## Running

```sh
cargo test --manifest-path sensors/rust-sensor/Cargo.toml

# Offline replay (no libraries needed)
cargo run --manifest-path sensors/rust-sensor/Cargo.toml -- \
  --leases sensors/rust-sensor/tests/fixtures/leases.txt \
  --pcap sensors/rust-sensor/tests/fixtures/tcp_established.pcap

# Live capture to Kafka (libpcap + librdkafka; needs CAP_NET_RAW on the gateway)
cargo build --release --features live,kafka --manifest-path sensors/rust-sensor/Cargo.toml
pi-agents-sensor --leases /var/lib/gateway-agent/dnsmasq.leases --interface wlan0 \
  --kafka pi-agents-kafka-bootstrap.iot-security:9092 --gateway-id gw-1 \
  --spool-dir /var/lib/pi-agents-sensor/spool
```

Fixtures in `tests/fixtures/` are generated by `tests/fixtures/generate.py`
(standard library only); rerun it after changing a scenario.

## Container image and deployment

`Dockerfile` builds the binary with `live,kafka` on `rust:1.94.0-slim-bookworm`
and ships it on `debian:bookworm-20260918-slim` with `libpcap0.8`
(librdkafka is linked statically). `docker-build.yml` publishes
`ghcr.io/kacperjarocki/rust-sensor:{latest,sha-<8 chars>}` for `linux/amd64`
and `linux/arm64` on pushes to `main`. Build locally on an arm64 machine with:

```sh
podman build -t localhost/pi-agents-sensor:dev sensors/rust-sensor
```

The Helm chart runs it as a DaemonSet when `sensor.enabled=true`
(`charts/pi-agents/values-sensor.yaml`):

- scheduled only on nodes labelled `node-role.kubernetes.io/gateway=true`;
- `hostNetwork` to capture on the AP interface (`sensor.interface`, default
  `wlan0`) and `ClusterFirstWithHostNet` DNS to reach Kafka;
- root with every capability dropped except `NET_RAW`, read-only root file
  system, no privilege escalation;
- `GATEWAY_ID` = node name; event IDs are `<node>/<capture_sequence>`;
- `/var/lib/gateway-agent` (dnsmasq leases) mounted read-only, re-read when
  it changes;
- spool on `hostPath` `/var/lib/pi-agents-sensor/spool` (2 GiB, 64 MiB
  segments) so a pod restart keeps unacknowledged events;
- limits 1 CPU / 512 MiB; liveness fails when the status file
  (`/run/sensor/status`, rewritten every 10 s) is older than 60 s.

Pin `sensor.image.tag` to a `sha-<8 chars>` tag in deployed values. To check a
deployment, connect a client to the IoT Wi-Fi, generate traffic, and consume
`traffic.flows.v2`; the sensor's stderr prints frame, flow, unattributed and
delivery counters every 10 s.
